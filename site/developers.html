Overview

Level AI's agents design levels for puzzle games, play each one hundreds of times with bot players, and tune it to a target difficulty. This API gives your tools those levels as JSON: the level itself, the difficulty we aimed for, and the difficulty we measured.

  • Base URL: https://levelai.vercel.app/api
  • Format: JSON over HTTPS, including errors.
  • Auth: the public endpoints need no key. Endpoints under /api/studio need your developer key in an Authorization: Bearer lvl_… header.
  • Stability: fields are only ever added, never renamed or removed. Ignore fields you don't know.

The examples on this page are real responses from the live API, taken Nov 7, 2026, 6:20 PM PT. At that time no level had passed testing yet, so the level lists were empty. Where a real level would appear, a sample is shown and labeled as one.

Quickstart

Get a key, then fetch levels with any HTTP client. Reading public levels doesn't need the key; it's for the studio endpoints and your coding agent.

1. Get a developer key

We email your key to you. It identifies your studio. Keep it private, like a password.

2. List the games

Request
curl https://levelai.vercel.app/api/games

3. Get the newest levels for a game

Request
curl "https://levelai.vercel.app/api/levels?game=match3&limit=5"

Each level in levels holds the level JSON in level. Load it into your game, or save level_id to fetch it again later.

4. Check your studio's levels

Request
curl https://levelai.vercel.app/api/studio/levels \
  -H "Authorization: Bearer $LEVELAI_KEY"

The level object

Every endpoint that returns levels uses this shape.

FieldTypeDescription
level_idstring (UUID)Stable ID.
game_idstringWhich game the level is for. The shape of level depends on it.
levelobjectThe level itself. See level JSON by game.
target_win_ratenumberThe share of players we aimed to have win, from 0 to 1.
measured_win_ratenumber or nullThe share our reference bot actually won in testing. See how levels are tested.
statusstringaccepted (passed testing) or published (also released in a pack).
created_atstringWhen the level was designed.

Webhooks

There are no webhooks yet. To pick up new levels, poll GET /api/levels with since set to the last updated_at you saw. Every few minutes is plenty: new levels take several minutes each to test.

Connect your coding agent

Level AI is also an MCP server (Model Context Protocol), so coding agents such as Claude Code, Cursor, and Codex can call it directly. Replace YOUR_KEY with the key from your email.

  • Server URL: https://levelai.vercel.app/studio-mcp (Streamable HTTP)
  • Auth: Authorization: Bearer YOUR_KEY

Bring your own generator

If your game already has a level generator, connect it, and we build your level packs with it. Your generator makes each level in your own format. Your own bot or solver plays it, since only you can run your game. Our agents tune each level to its target difficulty and deliver the pack.

How a pack works with your generator:

  1. For each level in the pack, we ask your generator for a level at a difficulty setting from 0 (easiest) to 1 (hardest).
  2. We send that level back to your evaluate endpoint, which plays it 100 times with your bot and tells us how many games it won.
  3. If the win rate is within 5 points of that level's target, or within 8 points with the target inside the 95% interval of the measurement, we keep it. Otherwise we move the difficulty setting toward the target and ask for a new level. Each level gets up to 6 tries.
  4. We save the levels, and email you the pack with each level's target and measured win rate, and the JSON in your format.

The protocol

Your generator is an HTTPS endpoint with a base URL, for example https://levels.yourstudio.com/levelai. It answers three operations. Each one is a POST with a JSON body and a JSON answer.

OperationRequest bodyAnswerTimeout
POST {base}/generateseed (integer), difficulty (0–1), optional params (object), optional contextlevel (your level JSON, an object), optional meta (object)20 s
POST {base}/evaluatelevel (what your generate returned), runs (integer), seed (integer)wins, runs, optional solvable (boolean), optional min_moves, optional bot (your bot's name)90 s
POST {base}/validate (optional)levelok (boolean), optional errors (strings)10 s
  • **difficulty** is the only setting we tune. Make higher values harder. It doesn't need to be linear.
  • **seed** is ours. The same seed and difficulty should give the same level, so a level can be remade.
  • **context** says where the level goes: { "pack_level": 3, "pack_size": 20, "target_win_rate": 0.7 }. It's for your information. You can ignore it.
  • **evaluate** should play the level as a player would, runs times, seeding your bot from seed. Return solvable: false if your own check says the level can't be won; we then ask for another one.
  • **validate** is optional. Answer 404 if you don't offer it. If you do, we call it before evaluate, and skip a level it rejects.
  • Answer with HTTP 200 and JSON. We retry a timeout, a network error, a 429, or a 5xx up to 2 more times. We don't retry other 4xx answers.

If your endpoint fails 3 calls in a row, we pause calls to it for 2 minutes. A pack then stops where it is: you get the levels that passed, marked as short, and a person on our team follows up. We never fill the gap with levels from our own games, since they wouldn't be in your format.

Verify our signature

Every request carries an X-LevelAI-Signature header: t=<unix seconds>,v1=<signature>. The signature is the hex HMAC-SHA256 of <t>.<raw body>, keyed with the signing secret you got when you registered. Check it on the raw body before you parse the JSON, and refuse requests older than 5 minutes. Requests also carry X-LevelAI-Generator (your generator's id) and X-LevelAI-Request (a unique id for the call).

Node.js
import { createHmac, timingSafeEqual } from "node:crypto";

export function verifyLevelAiSignature(secret, rawBody, header) {
  const parts = Object.fromEntries((header ?? "").split(",").map((p) => p.trim().split("=", 2)));
  const t = Number(parts.t);
  if (!Number.isInteger(t) || !parts.v1 || Math.abs(Date.now() / 1000 - t) > 300) return false;
  const expected = Buffer.from(createHmac("sha256", secret).update(`${t}.${rawBody}`).digest("hex"));
  const given = Buffer.from(String(parts.v1));
  return given.length === expected.length && timingSafeEqual(given, expected);
}

Register your generator

Send your generator's name, its genre, and its base URL with your developer key. The genre is one of match3, watersort, racer, or lotescape (or match-3, sort, lane-racer, parking). Set format to levelai only if your level JSON uses our format for that genre, so we can link playable previews. Otherwise leave it out.

Request
curl -X POST https://levelai.vercel.app/api/studio/generators \
  -H "Authorization: Bearer YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "Our level generator", "genre": "parking", "base_url": "https://levels.yourstudio.com/levelai"}'

  • **Save signing_secret right away.** We show it only once. We keep it encrypted and use it only to sign requests to you.
  • The base URL must use https and a public host name.
  • Registering again for the same genre replaces your generator and gives you a new secret. Update your endpoint before your next pack.
  • GET /api/studio/generators lists your generators and their last test result, never the secret.

How we use it

Once your generator passes its test, every level pack your studio orders in that genre is built with it. You get one email when the pack is ready. It says which levels came from your generator, the win rate your bot measured for each, the difficulty setting that got it there, and how many tries each level took. The pack's JSON link returns your levels exactly as your generator made them.

Example generator

Our example generator, at https://levelai-sample-generator.vercel.app, stands in for a studio. Rate limits and errors

Rate limits

No rate limit is enforced today. Please keep it under one request per second. Public responses can be cached: /api/levels/{id} and /api/packs/{id} for 5 minutes, /api/games for 1 minute, and the lists for 30 seconds. Studio responses are never cached. If we add limits, we'll document them here first.

How levels are made and tested

Each level goes through four agents before this API serves it:

  1. Designer writes a new level for the game, following the game's rules, and gives it a target win rate (for example, 40% of players win).
  2. Solver bots play the level automatically, up to 200 games per bot (100 for match-3). A slow run can stop early at a time limit, but never before 20 games; the tested count is part of every result. For every game except match-3, an exact solver also checks that the level can be won and finds the fewest moves.
  3. Tuner compares the target with the win rate of the reference bot, the bot that plays most like a person. Within 5 points, it accepts the level. Otherwise it makes one small change, such as one more move, and tests again. After 4 rounds it rejects the level instead.
  4. CEO agent publishes accepted levels in packs and adjusts plans from how real players do.

What the numbers mean, honestly:

  • measured_win_rate is how often our reference bot won, not real players. Bots are a stand-in for people. Real play can differ.
  • Levels that miss their target after tuning are rejected and never appear here.
  • Nobody hand-checks each level. If one looks wrong, tell us at the address in the footer.

What's not here yet

  • Levels for your own game without a generator. Without your own generator, our agents make levels in our own games. To get levels in your game's own format, bring your own generator. /api/studio/levels shows only samples we've sent you.
  • Webhooks. Poll /api/levels with since instead.
  • Writes. The API is read-only. You can't upload levels or change a target.
  • Real-player win rates. The API returns the measured bot win rate, not live player results.
