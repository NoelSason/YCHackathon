# Rhythm Level Editing with the Official Editor

Use this skill when the user requests help creating or reviewing an original level in the
Geometry Dash editor, using a user-provided mobile device controlled through Mobilerun.
Reference the [official Geometry Dash Editor Guide](https://www.robtopgames.com/files/GDEditor.pdf)
for editor controls and features. This is an editor workflow skill; it does not make Geometry Dash
or its assets part of our product.

## Boundaries

- Use only an existing, user-authorized Mobilerun device with the game already installed. Do not
  provision, reset, release, install, purchase, sign in, or change account settings.
- Keep work to a new local draft level. Never edit, delete, upload, share, rate, or publish a level
  unless the user separately asks for that specific action.
- Make original layouts and level names. Do not copy official levels, names, art, icons, effects,
  or music.
- For levels intended for our product, use royalty-free or CC0 music and record its license. Do
  not copy Geometry Dash files or assets into our product.
- Mobilerun remote taps are not proof of frame-exact gameplay or solvability. Do not claim the
  level is beaten, solver-verified, or difficulty-calibrated from remote phone play.

## Mobilerun workflow

Use the attached Mobilerun MCP Agent tool to carry out bounded, plain-language tasks on the
existing device. Follow the Mobilerun Agent default. Use direct Phone controls only when the Agent
cannot reliably perform a specific editor action and the needed Phone tool is available. Do not
guess MCP tool names or signatures.

1. Inspect the device state and confirm the game is open and ready. If it is not installed or the
   app requests login, purchase, permissions outside the task, or an account action, stop and
   report the blocker.
2. Ask for the level brief: name, target duration, song or beat reference, intended difficulty,
   gameplay mode, and mechanics to include or avoid.
3. Ask Mobilerun Agent to navigate to the local Create list and make a new level. The official
   guide describes the editor's Create list and New action; follow the visible mobile UI when its
   layout differs from the guide screenshots.
4. Build the requested layout in small sections. Use screenshots after each section and make
   corrections based on the visible result. Place gameplay cues with readable spacing and avoid
   dense clusters that obscure hazards.
5. Save the draft with the editor's Save action. Do not choose upload or publish actions. The
   official guide describes Save and Play as saving and starting a test attempt; use it only for a
   visual/load sanity check, not as proof of a successful completion.
6. Report the local level name, the editor actions completed, screenshots or observations
   returned by Mobilerun, and anything not verified. Leave the device and account state intact.

## Mobilerun task guidance

Keep each Agent task narrow, use a bounded step limit, and ask it to stop before any upload,
sharing, account, purchase, or destructive action. Prefer a sequence of tasks (open/create, build a
section, save, inspect) over one long task. Use the status/result from the Mobilerun task and its
trajectory screenshots when available; never invent a save confirmation or visual result.

## Completion report

State whether the level was saved locally and whether it was opened for a visual check. Include
Mobilerun's task outcome and any observed issues. Clearly label gameplay completion, exact timing,
solvability, and player difficulty as unverified unless supported by a separate solver or measured
playtest.
